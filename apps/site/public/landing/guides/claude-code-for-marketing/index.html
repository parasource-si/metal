claude code for marketing that gets past the blank brief

the draft sounds great. the delivery promise is made up. give a claude code bot the approved facts and ask it to find those gaps before customers do.

by the Metal team · checked 12 november 2026 · how we made this

it can review briefs, compare copy with approved claims and organise a content inventory. in Metal, attach the files and text the job. repeat a useful review as a routine.123

the brief comes before the copy

give it the brief you would give a writer. attach the product facts, audience, offer, deadline and writing rules. ask what is missing before asking for copy. a missing price should come back as a question.

in dusk, drop files into chat or choose attach files. the work appears in chat and lives in the bot’s folder or your chosen project folder.2

keep the source packet beside the draft so you can trace each promise.

pick one job you can inspect

hand it the review you keep putting off. start with a job whose answer you can judge:

  • brief review: quote contradictions with approved facts
  • copy review: separate unsupported claims from style edits
  • content inventory: group overlapping titles before proposing another article

keep each job in its own thread and compare the answer with the files. need fresh material? market research covers that separate request.

get the friday review without remembering to ask

a routine can bring you the claims that need a human decision. name the folder, time and destination. say when to stay quiet and what to do if a file is missing.

try: "every friday, read new briefs in the campaign folder. list claims missing from approved-facts.md here. ask before changing anything."

describe that job in chat to create a dusk routine. its card has edit, pause, undo and next runs. automations holds the calendar and run history.3 keep the final send separate, as in the newsletter workflow.

claude code has a separate cloud scheduler

you may already have the scheduler you need. as of 12 november 2026, claude code calls its routines cloud scheduled tasks. each saves a prompt, repositories and connectors.

they can start on a schedule, an api call or a github event. anthropic’s infrastructure runs them, and runs count against plan usage.4

that may suit a marketing site you manage as code. a dusk routine uses a different setup. the scheduled-task explainer separates cloud tasks, local desktop tasks and /loop.

approval belongs at the point of publishing

get the copy ready before giving it a way to publish. reviewing files needs no social account. connect an app only when the job needs it, with access chosen for that bot.

dusk reads and drafts freely. sends ask first unless you set a daily amount. careful with Full access: a bot there with no sending rule can send up to 25 a day without asking. give it Ask every time.52

page edits follow different rules. keep access read only or say "ask me before you change anything". social posting covers publication.

good writing can still make a bad promise

read the version customers will see. match names, prices, dates, links and promises to the source packet. a bot cannot know a private launch decision you never gave it.

customer results, testimonials and search demand need evidence of their own. a brief with none cannot support those claims. ask for fresh research separately when the files cannot answer the question.

the win is catching the invented delivery date before it becomes a customer’s expectation.

ask "which claim can you not support?" before asking "can you make it punchier?"

try it in 2 minutes

  1. attach a short draft and its approved fact sheet
  2. ask for unsupported claims only, with no edits
  3. open the fact sheet beside each flagged sentence
  4. correct the review before repeating the job

what it looks like

invented example: nadia reviews a launch draft.

before

the draft promises friday delivery. the approved brief gives a launch date but no delivery promise.

after the bot

an illustration with made-up names and numbers.

before the campaign goes out

  • every price and date matches the approved facts
  • customer claims have real evidence
  • you checked the final wording, not an earlier draft
  • publishing and page edits have clear review rules

mistakes people make

asking for copy with half the brief missing

ask for missing facts first. a fluent guess is still a guess.

letting one good draft justify automatic publishing

keep review on the version customers will actually see.

questions

can a non-developer use claude code for marketing?

yes, attach a draft and the approved facts. choose the bot’s ai in dusk and ask it to flag unsupported claims. you can judge the answer against those files.12

will a marketing bot publish without asking?

use ask every time for sends. a daily amount lets the bot send within that allowance. page edits need read-only access or an ask-first instruction; they follow different rules.25

will the weekly review run with my laptop shut?

local dusk routines stop when the laptop sleeps. dusk cloud keeps them running. claude code’s own cloud tasks also run away from your laptop, through a separate setup.34
