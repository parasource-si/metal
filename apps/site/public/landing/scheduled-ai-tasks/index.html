scheduled ai tasks: what runs, where and when

stop asking for the same morning brief every morning. claude, chatgpt, gemini and grok can repeat work, with different timers, triggers and limits as of 12 november 2026.

by the Metal team · checked 12 november 2026 · how we made this

dusk routines belong to a bot whose ai you choose. start in the app you already use if it fits. choose a separate bot when its own job, chats and memory help.

what the schedulers currently offer

match the limit to the job you need repeated. as of 12 november 2026, vendors count active schedules, runs per hour and timing options differently. an unstated limit still needs an answer from the vendor.

choose a time or a reason to start

use a clock for deadlines and an event for arrivals. a breakfast digest has a useful delivery time. a new issue needs attention only after it opens. don't pay for frequent empty checks when a quieter review would do.

as of 12 november 2026, chatgpt supports event tasks on plus, pro, business, enterprise and edu. free and go do not. claude code cloud tasks support github events and api calls.23

choose the trigger for the app that will actually run the job. compare claude tasks or chatgpt limits before choosing a plan.

ten jobs with something new to read

repeat the job, not the same stale answer. these are prompts to adapt, not measured results or vendor feature promises. give the bot access to the named files or connected app first.

  • daily priority, weekdays at 8: read the current plan in the project folder. suggest the first decision. stay quiet if nothing changed.
  • meeting rehearsal, tuesdays at 9: read this week's new briefing files. give three questions to practise. skip old briefs.
  • friday reflection at 4: read this week's project log. ask what went well and what to change. don't infer outcomes from task names.
  • evening study check: read new study notes in the course folder. quiz me on five terms. use memory notes to avoid repeating mastered terms.
  • monday writing nudge: read drafts changed this week in the writing folder. give one prompt for the unfinished part.
  • wednesday vocabulary: read new project documents. explain one unfamiliar term and keep a memory note of terms covered.
  • thursday contradiction check: inspect changed proposals in the proposals folder. flag conflicting statements. skip unchanged files.
  • saturday travel prep: until the trip, read the current travel checklist file. ask which unresolved items need a decision.
  • sunday reading review: compare articles added to the reading folder this week. list disagreements. skip weeks with fewer than two articles.
  • monthly reset: on the first, read the current goals file and last month's log. ask what to keep before suggesting new goals.

keep the first version read only. a question can help without granting permission to edit your work.

make a dusk routine by saying the job

the schedule card is where you catch a misunderstanding. tell the bot what to repeat, when and where the result goes. its card shows the schedule and next runs. edit, pause or undo there. automations has a calendar and run history.8

add a quiet rule, such as "if the document hasn't changed, say nothing". inspect the first few runs. if the time is wrong, ask which time zone the routine uses.89

start with reports in chat. reading and drafting can happen freely. keep these routines read only. for later app edits, write "ask me before you change anything"; they do not automatically wait for approval.10

a timer cannot keep a laptop awake

a morning brief that never came usually needs an awake machine. as of 12 november 2026, current cowork tasks run remotely. older local tasks created before 6 october stay local. claude code desktop tasks need an awake machine; grok bot lists cloud routines.1116

local dusk routines stop during sleep or when the app closes. missed by less than 12 hours? a run happens once on return. older runs skip.8 choose an always-on home if the delay makes the result useless.

gemini schedules prepare within their own delivery window. grok tasks distinguish automations from bot routines. read current provider terms and scheduler docs before moving unattended work.

try it in 2 minutes

  1. choose one job you already repeat
  2. name a source that changes between runs
  3. try the job once and inspect the result
  4. add a schedule with a quiet rule

if nothing changed, silence is a useful result.

mistakes people make

repeating a one-off comparison every week

read new or changed files, and skip unchanged material.

choosing a timer before finding the input

confirm the bot can reach the current source.

filling every schedule slot

keep only routines whose results you actually read.

quick checklist

  • the input changes between runs
  • the bot can reach that input without earlier chat messages
  • the timing fits the scheduler's limits
  • the result has a clear destination
  • the routine knows when to stay quiet
  • the running machine will be available

questions

what are people actually using scheduled ai tasks for?

start with reading, practice or planning. choose one repeat result you can judge quickly. keep it only if it earns the interruption.

can scheduled tasks run when my laptop is closed?

only if their running machine stays on. as of 12 november 2026, cowork and code offer remote tasks; grok bot offers cloud routines. local dusk needs an awake machine, or dusk cloud.1268

is the old chatgpt agent still the scheduler to use?

use the current tasks docs. as of 12 november 2026, openai says chatgpt agent is no longer available. it points to chatgpt work for longer tasks. old agent quotas do not describe current scheduling limits.123
