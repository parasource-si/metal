Metal/integrations

an obsidian helper that works with your note files

your unanswered questions are scattered across notes you keep reopening. give a local Metal the obsidian vault as its project folder and ask it to bring those questions together, with filenames.

by the Metal team · checked 12 november 2026 · how we made this

it works with markdown files, so there is no obsidian sign-in. the bot’s own memory opens in obsidian too, separately from your project vault.

what a bot can do with Obsidian

get the thread running through your notes without reopening them all.

obsidian work here uses markdown files on your computer. give a local bot the project folder and name the notes it may read. ask for recurring questions, written commitments or filing proposals in chat. no obsidian sign-in is needed.

the bot also keeps its own markdown memory. open that from its memory settings in obsidian; it is separate from the vault you choose for project work.

connect Obsidian

point it at the folder where the notes live.

run the bot on that computer, choose the project folder and name the reading area. ask for filenames beside its findings so you can go back to the original note.

the bot’s own memory lives under .duskbot/workspaces/<bot>/. read and edit it in memory settings. those notes stay separate from your project vault.

routines to copy

let the notes come back as questions worth answering. each routine reads a named area and brings its findings to chat. start with the part of the vault you keep meaning to revisit.

reading note review

every saturday at 10, read markdown notes in this project’s reading folder. group unanswered questions by topic and name the file behind each one. return the list here. never edit notes or search outside that folder.

saturdays at 10:00 · open reading questions grouped by topic, with filenames

weekly journal thread

every sunday at 7 in the evening, read this week’s files in the journal folder. list commitments separately from ideas i was only considering. keep the review here. never change the journal files.

sundays at 19:00 · a review of written commitments and tentative ideas

filing proposals

on the first day of each month at 4, inspect loose markdown notes at the root of this vault. suggest a folder for each, using only existing folder names. explain uncertain choices here. ask me before you change anything. do not move or rename files yet.

first day of the month at 16:00 · a filing plan with uncertain choices left open

what it asks you first

get the findings in chat before changing the vault. local file edits use the computer approval setting. start on ask for approval; auto-accept edits permits file changes. there is no obsidian connected-app grant to set read only.

the filing routine above asks the bot to wait before moves or rewrites. keep that instruction when you adapt it.

what it cannot do

  • there is no obsidian sign-in or action list here. the bot works with files.
  • local routines need an awake computer. they stop when it sleeps or dusk closes. a paired phone also needs that computer running.
  • a cloud-shared folder is not a writable local vault. sharing gives cloud bots a read-only copy, updated while your computer is on. use a local project folder for edits.

the vault and memory have different jobs

your project notes and the bot’s memory can sit side by side. the vault holds material you chose for the task. memory holds the bot’s own notes; opening it in obsidian keeps those jobs separate.

inspect and edit memory in its settings. turning off let this bot use memory stops the bot using it and leaves the files on disk.

questions are a better first job than moving files

find the idea you kept coming back to. for study notes, ask which questions recur and have it name the files behind them.

for file organisation, ask for a move plan. if the notes live in notion, use its connected-app permissions and actions instead.

try it in 2 minutes

  1. choose a small folder of markdown notes
  2. give a local bot that project folder
  3. ask for unanswered questions with filenames, no edits
  4. open the note behind one question and compare the wording

ask it to name the note behind every question. you will want the context when you come back.

mistakes people make

asking it to "tidy everything"

name one folder and request a plan before edits.

assuming local files mean local ai

look at the bot’s model choice. local files can still send text to an ai provider.

questions

can claude read my obsidian vault?

yes, through files you choose. a Metal bot using your chosen ai can read a local project vault. name the notes and request no changes for a reading job.

do i need an obsidian mcp server?

the local-file setup needs no mcp server. dusk also supports trusted mcp servers, but we have not evaluated a particular obsidian server or plugin.

do the notes stay only on my disk?

the files are local; the ai may not be. text used for the job goes to your chosen ai provider. choose a local model if you want that route. see privacy and data.
