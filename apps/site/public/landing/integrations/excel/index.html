what a bot can do in Excel

choose a connected workbook or attach the file.

  • the excel toolkit uses composio's microsoft excel connection. its workbook actions are separate from local attachments.
  • choose a connected workbook for ongoing app work.
  • attach the .xlsx when the job concerns that file.
actionMetal treats it aswhat you would use it for
Search Drive Filesreadlocate a workbook by name before inspecting its contents
List Worksheetsreadconfirm which sheets are present in that workbook
Get Worksheet Used Rangereadfind the occupied area of a sheet for review
Get Rangereadread budget vs actual for the range you name
List Table Rowsreadinspect the entries in a named workbook table
Update Rangechangewrite the numbers into the cells you named
Add Chartchangechart this month against last for the board deck
Export Workbook to PDFchangeprepare a pdf version of the workbook for review

composio, the connection service behind Metal's apps, lists 125 Excel actions (version 20261103_00, read 12 november 20264). Metal treats 60 as reads, 1 as sends and 64 as changes.

only actions starting with a read word (get, list, search) count as reads, so a read-only bot can't call the rest. a send reaches people or moves money, like create comment, and waits for your Allow unless you set a daily amount.

connect Excel

  1. open Connected apps in the sidebar.
  2. pick Excel and sign in on Excel's own page, so your password goes to them and never to a bot.
  3. choose which bots may use it, and whether each may only read or may also change things. your bookkeeper doesn't need your Excel.
  4. ask in plain words. reading and drafting happen freely; sending asks you first.

name the file and sheet before asking for an edit.

for connected work, choose excel in connected apps and sign in through microsoft. allow the workbook bot to use it.

for a file task, drop the .xlsx into chat or use attach files. say what to inspect and ask for the result as a file in chat. you can also give it a project folder.

routines to copy

get a useful report before handing over the cells. name the workbook, sheet and columns. let it write only after a few correct reports.

budget variance reading

every monday at noon, read the budget and actual columns in the connected planning workbook. list the largest differences with both inputs and each row label. keep currencies separate. change no formulas, values or formatting. if you cannot read a source value, say so.

mondays at 12:00 · a variance report here, with source values beside each difference

staffing table gaps

every wednesday at 9, read the allocation table in the connected staffing workbook. flag rows missing a person, week or assigned hours. name the row and missing field. leave entries and table order alone. if every row is complete, say so briefly.

wednesdays at 09:00 · a checklist of incomplete entries; the staffing table stays unchanged

month-end report copy

on the last day of each month at 3, find the connected monthly workbook for that month. show me its sheet names. wait for my confirmation before edits or export. after i confirm, make a pdf here for review. don't email it or reuse last month's file if the current one is missing.

last day of the month at 15:00 · the selected workbook and its pdf report here after your review

what it asks you first

keep the figures intact while you try the reports. give the bot read-only excel access. for cell changes later, restrict the action list and write "ask me before you change anything". cell edits use app permissions, so they can happen without a sending prompt.

attached-file work uses the bot's computer permissions instead. start on ask for approval while you see how it handles your workbook.

what it cannot do

  • edit a connected range with read-only access. a report here can stay separate from workbook writes.
  • react to each workbook edit through this connection. the excel catalog has no events. schedule the report instead.
  • finish local workbook work during sleep. the app and machine must stay awake. move timed jobs to an always-on bot machine when needed.

make the file route explicit

name the source and stop the copy hunt. for a one-off, say "review this attached workbook and return findings here". for recurring work, name the connected file and sheet.

ask which workbook the bot read. google sheets uses a different connection, so name that source separately.

decide where the report belongs

put the report where you will use it. generated files appear in chat and live in the bot's folder or a project folder you give it.

choose that folder for a file organisation routine. to email a report later, connect outlook separately and review the send there.

try it in 2 minutes

  1. drop in one .xlsx for a file-only trial
  2. name the sheet and a small range
  3. ask for findings here without edits
  4. compare one reported value with the workbook

ask for source values beside the conclusion. a variance without its inputs is harder to trust.

questions

can i just drop an excel file into the chat?

yes, attach the .xlsx. describe the job and ask for the result here. giving the bot that file needs no microsoft account connection.

is this an excel connection or desktop screen control?

the highlighted tools are app actions. they use composio's microsoft excel connection. attached-file work is another route. neither promises control of an open excel window.

can it watch every workbook edit as it happens?

schedule the report instead. the excel catalog has no triggers for workbook edits. choose how often you need fresh figures.
