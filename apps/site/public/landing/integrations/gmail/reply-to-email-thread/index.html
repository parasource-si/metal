Metal/integrations/gmail

reply in the gmail conversation you mean

get the answer back into the conversation where it belongs. the bot replies in an existing gmail thread, keeps its subject and quotes the last returned message.

by the Metal team · checked 12 november 2026 · how we made this

you name the recipients and can attach files. this action sends the reply; choose create email draft when you want to keep editing in gmail.

reply to email thread, in plain words

keep the answer where the conversation happened. the bot finds and reads the thread before replying to the people you name. it does not choose recipients from the thread by itself.

you can add files and your gmail signature. the complete message, attachments included, must stay under 25 mb. want to keep editing in gmail? ask for a draft instead.

a routine to copy

paste this into a chat with your bot

when gmail gets a proof query from joss at linden press, read the whole thread. read the matching correction file in the linked 'approved proof corrections' drive folder. use only that file to prepare a reply. show me recipients, text and attachment here. send only after i allow it. if no matching file exists, stop and tell me. never approve proofs or add recipients yourself.
when
when matching mail arrives; gmail checks about every 15 minutes
needs
gmail read and write; google drive read only; sending on ask every time

what comes back looks like this (an example)

awaiting approval
to: joss at linden press
subject: re: cover proof
reply: please use the revised subtitle from the attached brief.
attachment: cover-corrections.pdf

good jobs for it

  • answer a venue coordinator with the room choice you already agreed
  • return the corrected brief in the supplier conversation it belongs to
  • reply to an introduction without keeping unrelated people on cc

before it runs

Metal counts Reply to email thread as a send: it reaches people or moves money, so it waits for your Allow (unless you set a daily amount, or the bot is on Full access with no sending rule, which lets it send up to 25 a day). a bot you allow only to read can never call it.

the permissions Gmail asks for to run it: https://mail.google.com/, gmail.compose, gmail.modify, gmail.send.

how to start

  1. connect the right gmail account with read and write
  2. set sending on your behalf to ask every time
  3. name the sender, subject and intended recipients; ask it to read the full thread
  4. read the reply, open the file and allow the send; then try the recurring rule

limits worth knowing

  • careful with Full access: a bot there with no sending rule can send up to 25 a day without asking. give it Ask every time. a daily amount you set also lets it send on its own.
  • subjects repeat. add the sender or date so the bot finds the right conversation.

the details it works from

inputrequiredwhat it is
thread_idyesIdentifier of the Gmail thread for the reply.
ccnoCarbon Copy (CC) recipients' email addresses in format 'user@domain.com'.
bccnoBlind Carbon Copy (BCC) recipients' email addresses in format 'user@domain.com'.
is_htmlnoIndicates if `message_body` is HTML; if True, body must be valid HTML, if False, body should not contain HTML tags.
attachmentnoFile(s) to attach to the reply.
message_bodynoContent of the reply message, either plain text or HTML.

from composio's catalog for Gmail (action GMAIL_REPLY_TO_THREAD, read 12 november 20264). your bot fills these in from what you tell it.

try it in 2 minutes

  1. set gmail sending to ask every time
  2. find one thread by sender and subject
  3. ask for reply text and recipients here
  4. read the text and recipients, then allow

the subject keeps the conversation together. the sender and date tell you which conversation it is.

mistakes people make

assuming everyone on the thread gets the answer

name the recipients and inspect cc and bcc.

using a recurring job with corrections buried in chat

keep current corrections in a connected folder and name it.

questions

does it automatically reply to everyone on the thread?

you choose who gets the answer. name the recipients; the bot does not choose them from the thread. include to, cc and bcc in the preview.

can i have it leave a reply unsent?

ask for create email draft instead. the reply action sends when you allow it.
