Metal/integrations/google drive

put a new google drive folder in the right place

put the new project where you'll actually find it. your bot can create a google drive folder inside an existing parent.

by the Metal team · checked 12 november 2026 · how we made this

paste the parent link when names repeat; a name alone picks the first match. missing parents need separate creation. ask for a name and location preview before this write, then get the new folder link back.

where it helps

  • start a client project. prepare an empty destination under the confirmed client folder.
  • keep deliveries apart. add a dated folder beneath the production folder you already use.
  • make room for approved photos. create the child folder while leaving originals alone.

the short version

start the filing structure from the top. give the folder a name and an existing parent by exact name or link. the bot finds the parent, then creates the child inside it.

a nested structure takes separate steps: locate or create each parent before its child. missing parents won't appear automatically. the new folder starts empty; moving documents and changing sharing are separate jobs.

step by step

  1. keep the action list small. connect drive with read and write for finding and creating folders.
  2. give the parent link. ask the bot to show where it leads before creation.
  3. preview spelling and location. name each child and say to wait before creating it.
  4. open the child in drive. look at its parent folder. pause the routine when project intake ends.

send this to your bot

paste this into a chat with your bot

on the first monday of each month at 9, read new project briefs added last month to the shorelark commissions intake folder. use only confirmed projects that don't yet list a project folder.

open the commissions parent from its saved link. show proposed child names here and ask me before creating them. return links to the folders you make. if a brief already lists a folder, skip it. never choose a parent by name alone, move files or change sharing.

what can go wrong

  • repeated names choose the first match. use a parent link when the location matters.
  • parents must exist first. a nested path takes separate lookups or creation, top level first.
  • a new destination stays empty. leave moves and sharing outside this setup bot's actions.

permissions and asking first

Metal counts Create a folder as a change: it alters something in Google Drive, and the sending setting does not cover it. a bot you allow only to read can never call it.

the permissions Google Drive asks for to run it: drive, drive.file.

try it in 2 minutes

  1. paste the parent folder link
  2. name the child folder you need
  3. ask for its location before creation
  4. open the new folder and look at its parent

mistakes people make

trusting the name "projects"

many folders share that name. a link tells the bot which parent you mean.

asking for a deep path in one jump

create the top parent first, then its child. missing parents stop the job.

questions

can it create a whole nested folder path at once?

not in one go. each parent must exist before its child. the bot works down the structure one level at a time.

what if two folders have the same parent name?

a name alone picks the first match. paste the right parent link and ask the bot to show that location before creation.
