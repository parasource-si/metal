a google drive assistant that finds the right file

walk into the meeting with the approved packet, not the newer notes beside it. a google drive bot finds files, reads their details and inspects sharing.

by the Metal team · checked 12 november 2026 · how we made this

connect drive, choose its ai and start read only. it can hand you candidates and filing proposals. folder creation and moves need write access and an ask-first instruction if you want review.

what a bot can do in Google Drive

find the copy your team actually approved. give the bot a folder or file description and your approval rule. ask for the name, folder and last-changed date beside each candidate. a newer notes file can sit right next to the signed-off packet.

composio, the connection service behind Metal's apps, lists 105 Google Drive actions (version 20261104_00, read 12 november 20264). Metal treats 44 as reads, 4 as sends and 57 as changes.

only actions starting with a read word (get, list, search) count as reads, so a read-only bot can't call the rest. a send reaches people or moves money, like create comment, and waits for your Allow unless you set a daily amount.

connect Google Drive

  1. open Connected apps in the sidebar.
  2. pick Google Drive and sign in on Google Drive's own page, so your password goes to them and never to a bot.
  3. choose which bots may use it, and whether each may only read or may also change things. your bookkeeper doesn't need your Google Drive.
  4. ask in plain words. reading and drafting happen freely; sending asks you first.

keep the search in the right account.

connect the google account holding the files. name the folder or file to start from, and begin with read-only permission.

label work and personal accounts separately. you can connect up to five accounts per app. use the label in your request.

routines to copy

give the search a home and a rule. name the folder and explain how you mark approved files. each run should find current work, not rearrange drive behind your back.

find the meeting packet

every monday at 8, search my steering meeting folder in google drive for this week's packet. list candidate names and available last-changed dates here. use the approved-file naming rule in your memory notes. if several fit, show the choices. never move or rename files.

sharing review for handover

each thursday at 11, inspect files currently in my google drive handover folder. read the access checklist file in that folder and compare it with the permissions returned for each file. list differences and failed lookups here. never change permissions or create sharing links.

thursdays at 11:00 · sharing differences for the handover owner to review

folder move proposal

every friday at 2, inspect files currently in our google drive intake folder. match them to destination folders using the naming rules in your memory notes. show a filing proposal here and hold unclear matches for me. never create folders or move files.

fridays at 14:00 · a filing proposal, with ambiguous destinations left open

what it asks you first

plan the tidy-up with read-only access. dusk blocks folder creation, moves and sharing changes before they reach drive. a filing proposal needs none of them.

if you later allow moves, write "ask me before you change anything". moves and sharing changes skip sending approval.3

  • allow only the lookups, move file and create folder actions the job needs
  • broad write access can also allow deletion, emptying trash and public sharing without asking
  • comments and replies count as sends; those ask unless you allow a daily amount

careful with Full access: a bot there with no sending rule can send up to 25 a day without asking. give it Ask every time.

what it cannot do

  • move files while read only. the same limit blocks renaming and sharing changes. a filing proposal needs none of them.
  • export a google doc, sheet or slide while read only. dusk counts that export as a change. allow only that action if needed.
  • choose the approved copy without your rule. give a naming rule or reference list. if several files fit, the bot should show the choices.
  • run while its local host sleeps. dusk cloud keeps scheduled reviews running when your computer is off.

get the list right before organising

moving the wrong file makes a tidy mess. start with candidates and proposed destinations. use plain rules, such as where signed documents belong. unclear cases stay for review. file organisation has a broader routine.

for rows and formulas, use google sheets. drive also has spreadsheet-value actions. keep them outside a filing bot's allowance.

tell it how your team marks approval

the packet you need can be older than yesterday's notes. tell the bot what marks a file ready: an approved folder, a naming rule or a reference list.

use revisions and last-changed dates to trace the candidates. choose by your team's approval rule, then take the packet into the meeting.

try it in 2 minutes

  1. connect the right google account with read only access
  2. give the folder link and your approved-file naming rule
  3. ask for matching candidates with their last-changed dates
  4. choose the file before discussing moves

the filename final-final is a question, not an approval rule.

mistakes people make

calling the newest file the approved copy

use the team's actual approval rule.

giving a filing bot every write action

allow only the lookups and specific folder actions the job needs.

questions

can chatgpt find a file in my google drive?

yes, after you connect drive. choose your bot's ai and give it a folder, subject or naming rule. ask for candidates when the match is unclear.

will it reorganise drive without asking?

keep it read only for proposals. with write access, moves need no automatic approval. include the ask-first step when you allow them.

can i keep work and personal drive separate?

yes. label each account and name the label in the routine. dusk supports up to five usable accounts per app. choose app access separately for each bot.
