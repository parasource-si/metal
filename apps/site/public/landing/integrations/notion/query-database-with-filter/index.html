Metal/integrations/notion

ask for the notion records that match your conditions

stop scanning the whole tracker for a handful of rows. name the status, date or other condition you need. the bot asks notion for matches and sorts the results.

by the Metal team · checked 12 november 2026 · how we made this

give the database's own link. dusk counts this query as a change, so allow read and write for this exact action and its lookups.

what it does

get next week's confirmed bookings in one dated list. paste the database's own link, or ask the bot to find it. a page containing a tracker is a different thing.

the bot reads the field names and types, applies your conditions and sorts by session date. for a large list, tell it to keep going until notion has no more matches.

when you would use it

  • list confirmed studio bookings in the next fortnight
  • find equipment loans still out after their due date
  • sort approved grant applications by decision date
  • pull records from an archived year for a historical report

try it

paste this into a chat with your bot

at 17:05 each sunday, read the fields in my linked studio bookings database. find confirmed bookings with session dates in the coming week. sort by session date and keep going until notion has no more matches. put the dated list here. report missing dates or failed reads without guessing. never edit bookings, assign owners or change the database.
when
sundays at 17:05
needs
notion with read and write, limited to the query and its database lookups

what comes back looks like this (an example)

confirmed studio bookings
- monday: emma, portrait room
- thursday: noah, recording booth
sorted by session date. the week's matches are all here.

set it up

  1. connect notion. allow read and write for this query and the database lookups it needs.
  2. paste the database link. ask the bot to read field names and types first.
  3. try a filter with matches you already know. compare their dates and order.
  4. schedule the weekly query. Edit shows its next run. leave row-edit actions out.

how Metal handles it

Metal counts Query database with filter as a change: it alters something in Notion, and the sending setting does not cover it. a bot you allow only to read can never call it.

the permissions Notion asks for to run it: read_content.

where it stops

  • use the database link. the surrounding page's link can point the query at the wrong thing.
  • 100 rows is one batch. ask the bot to keep reading until it has every match.
  • sort by the date you plan around. created date and your booking-date column can give very different lists.
  • allow this query without handing over row edits. dusk classes it as a write, so read only blocks it. limit access to the query and its lookups.

try it in 2 minutes

  1. copy the database's own link into your request
  2. ask for confirmed rows due next week, sorted by the due-date column
  3. compare the matches with a filter you know

an empty list is lovely until you discover it filtered the wrong date column.

mistakes people make

pasting the page around an inline database

open the database and copy its own link.

sorting by row creation instead of the booking date

name the date column you actually plan around.

questions

why does a database query need read and write access?

dusk counts this action as a change. narrow the allowance to the query and its database lookups. you do not need general page edits.

can it combine a status with a date condition?

yes. the bot reads the real field names and types, then sends the combined conditions to notion.

does sorting the query rearrange my notion database?

no. sorting controls the returned list. it does not rearrange the database itself.
