Metal/integrations/notion

collect unresolved comments from a notion page with ai

walk into the review knowing what still needs an answer. a bot reads unresolved comments on a notion page or one block and brings the questions to your chat.

by the Metal team · checked 12 november 2026 · how we made this

it only reads, with access to that page and its comments. resolved discussions stay out. name the page or paragraph you mean, and ask it to finish the list before summarising.

fetch comments, in plain words

point to the discussion you actually want. name the page or paste its link. for a comment on one paragraph, point out that part and let the bot find it. page discussion and block discussion have different scopes.

the connection needs permission to read the page's comments. a sharing problem can look like a missing page. ask the bot to show the error instead of claiming nobody left feedback.

a routine to copy

paste this into a chat with your bot

each thursday at 14:35, read unresolved page-level comments on the notion page cresswell pavilion proposal. keep fetching batches until the results end.

list each question and its author here. say where access or an error stopped the read. show that the report covers page comments, with block comments and resolved discussions left out. never reply, resolve a discussion or rewrite the proposal. if nothing remains open, say so in one line.
when
thursdays at 14:35
needs
notion read only; share the proposal page with the connection and allow comment reading

what comes back looks like this (an example)

cresswell pavilion proposal

- alice: which entrance stays open during setup?
- mateo: where is the revised equipment list?

page comment list finished. block comments and resolved discussions excluded.

good jobs for it

  • prepare the next proposal. collect open questions before sending another version.
  • focus on a disputed paragraph. read its comments without searching every document.
  • give the author a clear queue. turn unresolved feedback into questions to answer.
  • get ready for the call. see which discussions remain open on the named page.

before it runs

Metal counts Fetch comments as a read: it looks and changes nothing. a bot you allow only to read can use it.

the permissions Notion asks for to run it: insert_content.

how to start

  1. keep this job read only. connect notion and allow the bot to read feedback.
  2. share the right page. include it among the pages the notion connection can open.
  3. test the scope. name the page or paragraph and ask for one read before scheduling.
  4. read the coverage note. it should name the page or block it covered. pause the routine when proposal review ends.

limits worth knowing

  • resolved means outside this list. this action doesn't return the full history of a discussion.
  • give the connection access before the review. a sharing problem can return "not found" even when the page exists.
  • long discussions arrive in batches. the bot should finish them before reporting a total.
  • page comments don't cover every paragraph. ask separately about a specific block when its discussion matters.

try it in 2 minutes

  1. share one notion page with the connection
  2. keep the bot on read only
  3. ask for unresolved page comments and their authors
  4. name the paragraph too if you need its block comments

ask the bot to finish with what it could not read. the missing part often matters more than the summary.

mistakes people make

treating an empty result as approval

confirm scope and access first. resolved or block comments can sit outside the result.

asking for everything under a page

name the paragraph when its comments matter. a page-level read does not cover nested discussions.

questions

can it reply to the reviewer as well?

not through this action. it only reads. posting a reply needs a separate action and permission.

why can the bot read the page but not its comments?

comment access can be missing. ask for the error. a failed read does not mean the discussion is empty.
