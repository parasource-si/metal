Metal/integrations/google sheets

add new records to the end of a google sheets table

get this week’s records into the sheet without replacing last week’s. the bot adds rows after your google sheets table.

by the Metal team · checked 12 november 2026 · how we made this

paste the link, name the tab and give the column order. the range helps it find the table’s end; it does not choose an exact empty cell. ask for a row preview and a pause before it writes.

what it does

use append for a log that keeps growing. each new entry gets a row after the existing table. the bot reads tab names and column headings before writing.

name the tab exactly and compare the proposed column order with its headings. “attendance” and “session log” can be different places in the same file.

say whether codes should stay literal text or whether sheets should interpret values such as dates.

when you would use it

  • finish the workshop register. add the attendance entries from your session records.
  • extend the loan log. append equipment loans after approval.
  • keep registrations together. add visitors in the register’s column order.
  • record fresh inspections. add completed checks without replacing older ones.

try it

paste this into a chat with your bot

every saturday at 12, read attendance files added this week to the pottery attendance folder in google drive. use only files whose names end in final. open the foxmere studio attendance spreadsheet, get its actual tab names and read the session log headers. compare existing rows to avoid adding the same session batch again. arrange new rows as session date, attendee name and attendance status. keep names exactly as written. show the rows and destination here. ask me before you change anything. after approval, append the rows and report where they landed. never change old attendance rows. ask if a batch looks duplicated.

set it up

  1. share the right sheet. connect sheets and paste the attendance file’s link.
  2. allow a narrow write. permit reading tab names, reading the table and appending rows.
  3. line up one row. compare its values with the column headings. say which codes must stay literal text.
  4. open the saved row. its date, name and status should sit under the right headings. pause the routine between workshop seasons.

from composio's catalog for Google Sheets (action GOOGLESHEETS_SPREADSHEETS_VALUES_APPEND, read 12 november 20264). your bot fills these in from what you tell it.

how Metal handles it

Metal counts Append Values to Spreadsheet as a change: it alters something in Google Sheets, and the sending setting does not cover it. a bot you allow only to read can never call it.

the permissions Google Sheets asks for to run it: spreadsheets, drive, drive.file.

where it stops

  • the table decides the next row. an unexpected gap or table boundary can change where entries land.
  • read back what matters. ask to see the saved rows instead of assuming the preview matches them.
  • retrying can duplicate records. append adds; it does not match and repair existing entries. look for the batch in the table before another attempt.

try it in 2 minutes

  1. paste the sheet link and tab name
  2. ask the bot to read the headings
  3. preview one new record in column order
  4. append after review and read the saved row

a row in the wrong columns is worse than a row still waiting to be added.

mistakes people make

retrying after an unclear result

read the table first. the first attempt may already have added the rows.

guessing the tab name

have the bot list the real tabs before choosing the destination.

questions

can i choose the exact row number it writes to?

use a cell update for that. append finds the table’s end inside the chosen range and writes after it.

does it correct a record that is already there?

no. it adds rows. fixing an existing entry needs a different action.
