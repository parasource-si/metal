an airtable assistant that learns the table before writing

find the missing owner before the launch stalls. an airtable bot can inspect your base, list records and open a row before handing you the gaps.

by the Metal team · checked 12 november 2026 · how we made this

name the base and table, then start read only. when the reports are right, you can allow intake rows, attachment uploads or corrections under rules you choose.

what a bot can do in Airtable

get the gaps that stop work, with the row beside each. find the right base, read its field definitions and open the records that need attention. your team's column names can hide rules; tell the bot what each required field means before allowing writes.

composio, the connection service behind Metal's apps, lists 28 Airtable actions (version 20261101_00, read 12 november 20264). Metal treats 8 as reads, 1 as sends and 19 as changes.

only actions starting with a read word (get, list, search) count as reads, so a read-only bot can't call the rest. a send reaches people or moves money, like create comment, and waits for your Allow unless you set a daily amount.

connect Airtable

  1. open Connected apps in the sidebar.
  2. pick Airtable and sign in on Airtable's own page, so your password goes to them and never to a bot.
  3. choose which bots may use it, and whether each may only read or may also change things. your bookkeeper doesn't need your Airtable.
  4. ask in plain words. reading and drafting happen freely; sending asks you first.

start the first review read only.

connect airtable in connected apps and give your records bot read-only access. name the base and table. ask it to describe the fields it will use.

when you allow writing, choose the exact actions the job needs. an intake bot doesn't need field or table changes.

routines to copy

start with the table that keeps catching you out. name its fields and explain what counts as missing. these routines read fresh records or files each time.

editorial readiness check

every monday at 9, read my airtable content table. find records due this week with missing titles, owners or assets. list missing values here. inspect attachment details where needed. leave publishing status and dates alone.

mondays at 9:00 · a short list of content gaps to fix before publishing

event logistics gaps

every thursday at noon, read upcoming records in my airtable event table. compare them with the venue and contact checklist in your memory notes. read record comments before calling a question unanswered. list gaps and uncertain answers here. never edit the records.

thursdays at 12:00 · venue and contact questions that still need an answer

approved intake capture

every weekday at 5, read new intake files in my project folder named approved intake. inspect the destination airtable fields. compare each item with existing records using the matching rule in your memory notes. show proposed new rows here and ask before adding them. report unclear matches instead of overwriting records. skip any item already present.

weekdays at 17:00 · new intake rows after your review, with uncertain matches held back

what it asks you first

get a useful review before handing over edits. read only lets the bot find gaps and show proposed rows in chat. airtable changes skip sending approval; the intake routine asks because its instruction says to.

when you allow writing:

  • choose record creation or correction only when needed
  • leave field changes, table changes and deletion out
  • write "ask me before you change anything" for supervised edits

what it cannot do

  • write with read-only access. it cannot add rows, upload attachments or repair records. it can show proposed values in chat.
  • guess what blank means. tell it whether an empty field means missing, unnecessary or waiting for a decision.
  • prove an item is new from its title. give a matching rule. send unclear matches to you instead of overwriting.
  • run on a sleeping computer. local jobs need an awake machine and open dusk app. cloud keeps them available with your computer off.

tell it what your fields mean

ready can mean three different things in the same company. tell the bot which fields it should read and fill, which values are required and how to find existing records.

a note column may carry a team rule nobody wrote into its name. explain it before allowing writes.

mostly cells and formulas? compare google sheets. work starts in a page? try notion.

make intake easy to review

small batches make bad matches easier to catch. name one target table and keep approved intake in a folder the bot can read.

after creating rows, ask it to return the saved records. compare those values with the source files. use a filing routine to plan where supporting files belong.

try it in 2 minutes

  1. connect airtable with read only access
  2. name one base and table
  3. ask for records due this week without an owner
  4. open the flagged rows and compare them with the report

a list of three missing owners beats a tidy summary that hides them.

mistakes people make

treating every blank as an error

explain which fields must have a value and which can stay empty.

adding rows without checking for existing records

give a matching rule and hold uncertain matches for your decision.

questions

can chatgpt work with my airtable base?

yes, through a connected airtable account. choose the bot's ai in dusk. name the base and ask for the missing owners in one table.

can it add records without changing the table structure?

yes. allow only record creation and its lookups. leave field and table changes out. the intake routine asks before adding rows because you told it to.

what is a useful airtable routine for everyday work?

find the gap that will delay friday. missing content owners, absent assets and unanswered event questions make useful first jobs. all can stay read only.
