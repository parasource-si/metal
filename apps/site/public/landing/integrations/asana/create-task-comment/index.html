turn your notes into a comment on the right asana task

stop making your team hunt through email for the latest date. a bot finds the right asana task and puts a plain text update beside it.

by the Metal team · checked 12 november 2026 · how we made this

you get the news where the work lives, with the project confirmed before posting. comments count as sends and ask first by default. set a sending rule when every comment needs your review.

create task comment, in plain words

a comment keeps the news with the work. give the bot the task's project and the words to post. it can look through project tasks, open the match and add your update to its activity feed.

this field accepts plain text only. html, rich headings and styled links won't carry over. use short lines that still make sense without formatting.

a routine to copy

paste this into a chat with your bot

on fridays at 11, read this week's emails from people at @tallowmere.com that confirm a new delivery date.

- find the matching task in the mobile checkout project in asana
- write a plain text comment with the new date, who confirmed it and when
- show me each task and comment here; post only the ones i allow

never change a task's due date or owner. if no email qualifies, say so briefly. don't invent a date or confirmation.
when
fridays at 11:00
needs
gmail read only; asana read and write for task lookup and comments

good jobs for it

  • keep test evidence close. post the result beside the task your team will review.
  • record a delivery change. quote the supplier's new date without editing the task deadline.
  • close a design question. add the answer you approved to the task's discussion.
  • leave a useful handoff. say what finished and which question remains open.

before it runs

Metal counts Create task comment as a send: it reaches people or moves money, so it waits for your Allow (unless you set a daily amount, or the bot is on Full access with no sending rule, which lets it send up to 25 a day). a bot you allow only to read can never call it.

how to start

  1. connect the two apps. give this bot gmail read only and asana read and write.
  2. careful with Full access: a bot there with no sending rule can send up to 25 a day without asking. give it Ask every time.
  3. try one update. open its task and activity feed before scheduling the friday run.

limits worth knowing

  • same title, wrong team. open the task in its project. the connected account needs access there too.
  • plain text means plain text. don't depend on html or rich formatting to carry the meaning.
  • keep the final word on comments. a daily sending allowance skips individual reviews.
  • sleep can cost you a run. a miss under 12 hours runs once when you return. older runs skip. dusk cloud runs on time.

from composio's catalog for Asana (action ASANA_CREATE_TASK_COMMENT, read 12 november 20264). your bot fills these in from what you tell it.

include who confirmed the date and when. a bare new date leaves the next reader guessing.

try it in 2 minutes

  1. name one task and its asana project
  2. paste one confirmed delivery update
  3. ask for the comment here first
  4. open the task in its project, then allow the comment

mistakes people make

posting under a familiar title

open the project too. repeated task names are an easy way to tell the wrong team.

rewriting the deadline along with the comment

say "comment only; leave dates and owners alone". a delivery note is not a reschedule.

questions

can it post the comment without changing the deadline?

yes, the comment leaves task fields alone. allow only task lookups and comments if that is the whole job.

will bold text and formatted lists carry over?

no rich formatting here. ask for ordinary text and short lines. html and styled emphasis won't survive this field.

what if two asana tasks have the same title?

choose by project as well as title. ask the bot to show both matches before posting. you name the work; it finds the task.
