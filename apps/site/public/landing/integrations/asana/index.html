an asana assistant for the work between tasks

walk into the handoff knowing what still blocks it. an asana bot can read tasks, comments, subtasks and dependencies together, then name the unfinished work and its owner.

by the Metal team · checked 12 november 2026 · how we made this

give that review to a Metal bot using the ai you choose. start read only. let the review earn your trust before allowing it to change tasks.

what a bot can do in Asana

find the missing prerequisite before the launch meeting. the bot can read the project, comments and dependencies together. these actions get you from "launch ready" to the task still holding it up.

composio, the connection service behind Metal's apps, lists 247 Asana actions (version 20261104_00, read 12 november 20264). Metal treats 118 as reads, 1 as sends and 128 as changes.

only actions starting with a read word (get, list, search) count as reads, so a read-only bot can't call the rest. a send reaches people or moves money, like create task comment, and waits for your Allow unless you set a daily amount.

connect Asana

  1. open Connected apps in the sidebar.
  2. pick Asana and sign in on Asana's own page, so your password goes to them and never to a bot.
  3. choose which bots may use it, and whether each may only read or may also change things. your bookkeeper doesn't need your Asana.
  4. ask in plain words. reading and drafting happen freely; sending asks you first.

keep the first project review read only.

in connected apps, allow the project bot to use asana. name the workspace and project, especially when projects share a name.

choose an exact list of allowed actions to keep task creation available. leave unrelated changes out of reach.

routines to copy

start with a question, not a workspace dump. name your project and send one of these. findings come back to your dusk chat before you allow task edits.

check tomorrow's handoff

every afternoon at 3, read tomorrow's tasks in the launch project in asana. read their subtasks and dependencies. list unfinished prerequisites and the person assigned, if assigned. return the checklist here. leave every task date alone. if nothing blocks the handoff, say so in one line.

daily at 15:00 · a checklist of unfinished handoff work in your chat

compare the status note

every monday at 10, read the website project's latest asana status update and current tasks. flag completion claims with unfinished subtasks. name the tasks. separate missing details from actual contradictions. return questions here; don't post a status update.

mondays at 10:00 · questions for the project owner; no status post

prepare a contractor return

every thursday at 2, find the named contractor's tasks in the design project in asana. read their comments. list questions still waiting for our answer, grouped by task. return the list here. never reassign tasks or post comments. if none need an answer, say so briefly.

thursdays at 14:00 · a task-by-task reply list for the contractor check-in

what it asks you first

keep the first review from becoming a reshuffle. read-only access blocks task creation, edits and section moves before they reach asana.

when you want edits, allow the particular actions and write "ask me before you change anything". due-date changes and reassignments do not automatically wait for an approval card.

what it cannot do

  • it cannot see projects your connected account cannot open. name the exact workspace and project when names overlap.
  • it cannot create tasks or correct assignments with read-only access. these review routines leave records alone.
  • it cannot review tomorrow's handoff from a sleeping desktop. keep the machine awake with dusk open, or use dusk cloud.

blocked needs evidence

put the unfinished prerequisite beside the claim that launch is ready. tell the bot what counts as blocked for your team. ask it to show what it found and what it couldn't find.

if delivery also lives in jira, connect it separately. teams working mainly in linear can start with that issue review instead.

keep the review small

one project and one decision are enough. can we hand this off? what needs an answer? does the status note match the tasks?

a workspace-wide summary buries the wrong assumptions. compare the early reports with their tasks, then edit or pause the schedule in automations.

try it in 2 minutes

  1. connect asana read only for one bot
  2. name the project and one task due tomorrow
  3. ask what unfinished dependencies it has
  4. compare the answer with asana

questions

what are people actually using an asana ai agent for?

try a check-in you already do by hand. read prerequisites, compare status claims or collect unanswered contractor questions. these routines return review lists without editing tasks.

can i use claude with asana without moving my tasks?

yes. the tasks stay in asana. connect it and choose your bot's ai. switching ai keeps the bot's chats and memory.

will the bot move deadlines without checking?

keep reviews read only to keep deadlines in place. for a later editing job, limit the allowed actions and tell it to ask first. deadline edits do not automatically wait for approval.
