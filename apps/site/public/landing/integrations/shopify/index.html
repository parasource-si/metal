Metal/integrations

a shopify assistant for stock and fulfilment exceptions

see the stock shortage before you promise the order. the bot can read shopify orders, location inventory and draft orders, then bring you a short exception list.

by the Metal team · checked 12 november 2026 · how we made this

start with the specific read actions. connecting shopify takes your own composio project key and sign-in setup; there is no managed sign-in here. add store writes only when the review gives you a reason.

what a bot can do in Shopify

ask for a short list of store exceptions.

which draft orders need a decision? which locations have low stock? ask for source records beside each point. use these specific reads first. don't assume every broad graphql action works for a read-only bot.

actionMetal treats it aswhat you would use it for

List Location Inventory Levelsreadread inventory levels at the location you name
Get orderreadinspect a known order when reviewing a fulfilment question
Get productreadread product details for a catalog correction list
Retrieve list of draft ordersreadreview drafts that still need a store owner's decision

List abandoned checkoutsreadinspect returned abandoned checkouts without sending recovery messages
Create a new draft orderchangeprepare an agreed draft order when you allow that change

composio, the connection service behind Metal's apps, lists 468 Shopify actions (version 20261104_00, read 12 november 20264). Metal treats 205 as reads, 16 as sends and 247 as changes.

only actions starting with a read word (get, list, search) count as reads, so a read-only bot can't call the rest. a send reaches people or moves money, like activate one-time charge, and waits for your Allow unless you set a daily amount.

composio has no ready-made sign-in for Shopify. connecting it needs your own composio project key and an auth config of your own, added under Settings, API keys. on dusk cloud, ask us first.

connect Shopify

  1. open Connected apps in the sidebar.
  2. pick Shopify and sign in on Shopify's own page, so your password goes to them and never to a bot.
  3. choose which bots may use it, and whether each may only read or may also change things. your bookkeeper doesn't need your Shopify.
  4. ask in plain words. reading and drafting happen freely; sending asks you first.

shopify needs your own composio setup.

there's no ready-made sign-in through composio. add your own composio project key under settings, api keys. create your own auth config before asking a bot to use shopify.

once connected, name the store and locations. only allow the bot that needs store access.

routines to copy

your store rules decide what needs attention. keep thresholds and age rules in a file the bot can read. these jobs report exceptions and leave store records alone.

location stock exceptions

every weekday at 7, read the stock minimums file in my store operations folder. read shopify inventory for the location named there. list items below their minimums with the returned quantity and location. show missing inventory data separately. never adjust stock or assume a delivery arrived.

weekdays at 7:00 · low-stock items at the chosen location, with missing data separate

draft orders needing a decision

every tuesday at 1, read the draft order age rule in my store operations guide. list shopify draft orders and show those needing a decision under that rule. include their order details. never complete drafts, send invoices or contact customers.

tuesdays at 13:00 · draft orders for the store owner to review

fulfilment desk check

every afternoon at 4, read the fulfilment exception rules in my store operations guide. list assigned shopify fulfilment orders available to this connection. highlight matching exceptions and read the known order details when needed. leave holds, routing and fulfilment status unchanged.

daily at 16:00 · a fulfilment desk note with the matching order records

what it asks you first

keep the stock review read only. that blocks draft creation, inventory adjustments and order edits. use the specific read actions, since broad graphql queries count as writes here.

inventory edits do not automatically ask first. if you add them later, say “ask me before you change anything” and allow only the actions needed.

customer messages and other sends ask first unless you allow a daily amount. careful with Full access: a bot there with no sending rule can send up to 25 a day without asking. give it Ask every time.

what it cannot do

  • connect through a ready-made shopify sign-in. prepare your own composio project key and sign-in configuration first.
  • use every broad query with read-only access. general shopify graphql orders, products and inventory actions count as writes here. use the specific highlighted reads.
  • fix stock or complete drafts while limited to reading. a stock warning tells you where to investigate. it does not change the quantity.
  • run the morning review on a sleeping laptop. local routines need an awake machine and dusk open. dusk cloud can keep them running while you are away.

give each stock warning a location and a minimum

find the shortage that could break a customer promise. name each location and its stock minimums. say how to report blanks and missing values. the bot should show the quantity shopify returns, with gaps on their own line.

keep incoming deliveries separate until stock says they arrived. bots for ecommerce covers the wider day.

read payments in their own account. an order record cannot tell you money arrived.

keep recovery messages as a separate job

read the order before making the customer a promise. abandoned checkouts can feed an internal review list. sending a recovery message needs a separate request.

if support uses whatsapp business, connect it separately. say which store facts belong in the reply. read the recipient and promise before allowing the send.

missing inventory data should get its own line, not quietly become zero.

try it in 2 minutes

  1. use your configured shopify connection
  2. choose one store location
  3. ask for its inventory without changing anything
  4. compare one returned quantity with the store record

before the first stock review

  • your custom connection works
  • the store and location are named
  • minimums live in a readable file
  • the bot has only the read actions it needs

mistakes people make

comparing stock across unnamed locations

pick the location before judging a quantity.

giving broad store writes to a stock reader

use the specific inventory reads and leave adjustments out.

questions

can claude help manage my shopify store?

yes, through the available actions after custom setup. try a read-only stock review for a location first. decide later whether the bot needs any store writes.

why is this not a one-click shopify connection?

composio has no managed shopify sign-in here. you need your own composio project key and sign-in configuration.

will it automatically change stock when it finds a problem?

read-only access prevents that. this routine reports exceptions. if you later permit inventory changes, tell the bot to ask before each change.
