Metal/integrations/jira

put a clear test update on a jira issue

give the next person enough detail to repeat your test. a bot turns your notes into a jira comment with steps, links and a clear result.

by the Metal team · checked 12 november 2026 · how we made this

it finds the issue from the project and problem you name. posting counts as a send and asks first by default. read the wording and audience before you approve.

where it helps

  • show how checkout failed. include the steps and observed result.
  • leave a release check people can follow. use links with descriptive words.
  • keep an investigation within its audience. confirm the existing project role first.
  • answer with evidence. separate expected behaviour from what you actually saw.

the short version

put the evidence beside the issue. the bot finds the work through jira search, then prepares a comment. it supports lists, bold text and mentions. clickable links need words attached, not bare web addresses.

you can limit a comment to a project role or group. check the actual names first. group restrictions need an administrator to enable them. if the audience can't be confirmed, stop.

step by step

  1. connect jira with read and write access so the bot can add comments.
  2. set sending on your behalf to ask every time. try one comment on an issue you can inspect.
  3. careful with Full access: a bot there with no sending rule can send up to 25 a day without asking. give it Ask every time.
  4. read the issue, audience and links before allow. schedule the weekly review once that looks right.

what can go wrong

  • group restrictions need setup. an administrator must enable them. role and group names can differ between projects.
  • bare web addresses won't become clickable. ask for links with descriptive words.
  • use ask every time to review each comment. a daily sending amount lets comments go out within that limit.
  • put the update on the right issue. match the project as well as the title.

permissions and asking first

Metal counts Add Comment as a send: it reaches people or moves money, so it waits for your Allow (unless you set a daily amount, or the bot is on Full access with no sending rule, which lets it send up to 25 a day). a bot you allow only to read can never call it.

the permissions Jira asks for to run it: write:jira-work, read:comment:jira, read:comment.property:jira, read:group:jira.

"tested on my phone" leaves everyone guessing. name the device, steps and result.

try it in 2 minutes

  1. name one issue and the test result
  2. ask for a comment draft without posting
  3. read who can see the comment and open its evidence links
  4. approve only the comment you read

before you post

  • the issue belongs to the right project
  • observed and expected results stay separate
  • links have words people can click
  • mentions and audience match your intent

mistakes people make

writing 'tested' with no device or result

say what you tried, where you tried it and what happened.

asking for 'internal' without an audience

confirm the project role or group. stop if it can't apply the restriction.

questions

can the bot make a jira comment internal?

it can request a role or group restriction. those names must fit your jira setup. ask it to confirm the audience before posting.

can it mention a teammate in the comment?

yes, by username or display name. ask for the mention only when you mean it. review the person alongside the proposed text.

does it support a test checklist?

yes, with lists and emphasis. say what passed, what failed and what nobody tried. give the next tester something they can repeat.
