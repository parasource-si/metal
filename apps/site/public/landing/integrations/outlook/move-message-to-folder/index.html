Metal/integrations/outlook

move an outlook email into the right folder

get completed claims out of your inbox and into the folder you'll search later. a bot finds the outlook message and destination, then moves it within the same mailbox.

by the Metal team · checked 12 november 2026 · how we made this

ask for a subject-and-folder preview before it moves anything. this is a write, so the sending setting won't pause it for review. you get a result for each move.

where it helps

  • close out a warranty claim. file the completed message under its existing project folder.
  • clear a handled confirmation. move it once its event details are in your plan.
  • repair a filing mistake. return one email to the folder it belongs in.
  • keep supplier mail together. move the chosen thread's individual messages into the same mailbox folder.

the short version

find both ends before moving anything. the bot looks up the exact email and destination folder. tell it to stop rather than choose a similar folder name. this stays within one mailbox; it won't transfer mail to a colleague.

if a move fails, have the bot find the message again before retrying. small batches make the result easier to inspect and avoid piling moves on at once.

step by step

  1. choose the mailbox. allow outlook read and write for this filing bot.
  2. find the destination first. ask it to list folders and show the one you mean.
  3. put review in the job. read one subject and destination together before allowing a move.
  4. inspect the result. open the destination after the first move. pause the routine if the filing rule becomes unclear.

send this to your bot

paste this into a chat with your bot

every friday at 11:55, read messages in my outlook folder warranties / ready to file for oakmarsh warranties. use that folder as the input, not previous chat messages.

find the existing warranties / completed folder. show each selected subject and destination here, then ask me before moving anything. move only the messages i confirm and report each result. never create folders, delete mail or guess a message. if nothing is ready, say so briefly.
when
fridays at 11:55
needs
outlook read and write; existing ready-to-file and completed folders in the chosen mailbox

what comes back looks like this (an example)

oakmarsh warranties
message: replacement hinge confirmation
from: warranties / ready to file
to: warranties / completed

message and destination found. ready for your decision.

what can go wrong

  • don't retry a stale lookup. if the move fails, find the email again before one more attempt.
  • large batches need patience. move a few at a time so you can track what happened.

permissions and asking first

Metal counts Move message to folder as a change: it alters something in Outlook, and the sending setting does not cover it. a bot you allow only to read can never call it.

the permissions Outlook asks for to run it: Mail.ReadWrite.

inputs

inputrequiredwhat it is
message_idyesUnique immutable ID of the Outlook email message to move.
destination_idyesThe destination folder ID, or a well-known folder name (e.g., 'inbox', 'deleteditems', 'drafts', 'sentitems').

from composio's catalog for Outlook (action OUTLOOK_MOVE_MESSAGE, read 12 november 20264). your bot fills these in from what you tell it.

try it in 2 minutes

  1. pick one email in the chosen mailbox
  2. ask the bot to find its destination folder
  3. review the subject and folder together
  4. confirm the move, then open the destination

start with one message. if its destination looks wrong, you have one correction instead of a missing inbox.

mistakes people make

assuming ask every time covers filing

that setting covers sends. put "ask me before moving anything" in the filing request.

retrying without finding the email again

look it up afresh after a failure. open the destination before repeating a move.

questions

can it make a new folder if it's missing?

not with this action. it moves mail into an existing folder. create the destination in outlook first.

will this move mail into a colleague's mailbox?

no, it stays in one mailbox. the source message and destination folder belong to the same user.
