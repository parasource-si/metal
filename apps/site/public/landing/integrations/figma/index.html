a figma bot that gathers the handoff details

the handoff shouldn't start with a hunt through comments. a Metal bot can read figma files, comments, components and variables.

by the Metal team · checked 12 november 2026 · how we made this

ask for the decisions still open or a handoff inventory, using the ai you choose. it gathers the context. it can't redraw every screen or turn the design into a finished product for you.

what a bot can do in Figma

walk into the handoff with the open questions already sorted. give the bot a file link and name the frames. it gathers comments, components and recent file context into a review agenda before anyone starts building.

composio, the connection service behind Metal's apps, lists 53 Figma actions (version 20261101_00, read 12 november 20264). Metal treats 36 as reads, 2 as sends and 15 as changes.

only actions starting with a read word (get, list, search) count as reads, so a read-only bot can't call the rest. a send reaches people or moves money, like add a comment to a file, and waits for your Allow unless you set a daily amount.

connect Figma

  1. open Connected apps in the sidebar.
  2. pick Figma and sign in on Figma's own page, so your password goes to them and never to a bot.
  3. choose which bots may use it, and whether each may only read or may also change things. your bookkeeper doesn't need your Figma.
  4. ask in plain words. reading and drafting happen freely; sending asks you first.

start with a file link and read only access. add figma in connected apps, sign in through figma and choose the bot. name the frames you want it to read. that is enough for a review agenda; variable edits can stay disabled.

routines to copy

pick the question holding up the handoff. these routines read figma and return private notes in dusk. they don't post review comments or edit the design.

review agenda

every wednesday at 11, read comments in the checkout figma file linked in your memory notes. group open questions by frame. separate decisions from small corrections and include the source comment. put the agenda here. never post, react or edit anything.

wednesdays at 11:00 · a review agenda grouped by frame, with source comments

handoff inventory

every thursday at 5, inspect the checkout frames listed in the handoff brief in our project folder. read their current components and styles from figma. list what the file answers and what still needs a person. return the inventory here. never change the design or create development tickets.

thursdays at 17:00 · a current component and style list, with unanswered handoff questions

design reference refresh

on the first tuesday each month at 9, read local variables and version history for the design library linked in your memory notes. return a current reference list and the version you read. compare with the last reference in our project folder. show the old and new values beside each change. never edit variables.

first tuesday of the month at 09:00 · a dated design reference tied to the file version

what it asks you first

keep the agenda in dusk until you want to post a comment. comments count as sends and stop at allow or deny by default. a daily sending amount lets them go out within that limit.

careful with Full access: a bot there with no sending rule can send up to 25 a day without asking. give it Ask every time.

variable edits don't ask first. leave them disabled for reviews. for an editing job later, add 'ask me before changing anything'.

what it cannot do

  • it isn't a general canvas editor. the action list covers variables and development resources, not drawing or rearranging every layer.
  • read only means no comments or variable edits. gathering a handoff doesn't need permission to maintain the design.
  • there's no figma event trigger. schedule these reads. local reviews stop while the computer sleeps.

turn the inventory into a decision list

hand the developer the question that is blocking the build. put frame references beside each open decision. components tell you what's in the file; a person decides which should ship.

if a decision becomes linear work, review the proposed issue before granting tracker writes.

bring the design brief to the code review

find the gap between the design and what shipped. a github bot reads code through its own connection. compare that evidence with the figma brief before signing off the build.

for exports and campaign assets, look at the canva actions. they cover different work and have different limits.

try it in 2 minutes

  1. connect figma as read only
  2. paste one file link and name a frame
  3. ask which comments need a decision
  4. open the source comments in the file

ask 'what needs a person?' before asking for a longer inventory.

mistakes people make

asking for a handoff without naming the frames

name the screens that matter. don't make the bot guess the scope.

giving a reviewer permission to edit variables

allow only reading actions until a separate job needs changes.

before the developer starts

  • the brief names the file and frames
  • open decisions stay separate from corrections
  • components and styles come from the current file
  • code claims have their own evidence

questions

can claude read my figma file?

yes, through a Metal bot's figma connection. choose claude or another ai, connect the account and allow that bot. give it the specific file or frame.

can it turn my design into a finished app?

no. a handoff is preparation. it can gather what developers need. you still check the build against the design.

will it post design feedback without telling me?

read only access blocks posting. if you enable comments, use the sending setting described above to review them. private dusk notes need no publication action.
