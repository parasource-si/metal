ask a bot to read web pages into a table

get the workshop dates and prices into a table without an afternoon of copying. give a bot a short list of pages and the fields you need.

by the Metal team · checked 12 november 2026 · how we made this

it reads them in its own browser and returns a table with sources. keep missing values and failed pages visible. good for 5 to 50 pages you'd otherwise copy by hand. wrong tool for crawling a whole site.

the routine

define a row before asking for a table. put a short list of permitted public links in a project file. name each field as you would to someone collecting it by hand.

paste this into a chat with your bot

every wednesday at 11, read the public workshop links in the page-list file in our project folder. use your own browser and stay within that list.

return one row per session: title, organiser, displayed date, displayed location, displayed price and currency, source link and reading date. copy dates and prices as shown. use 'not listed' for missing fields. don't calculate them. separate sessions on the same page into separate rows.

list failed pages separately. stop at access blocks, sign-ins or notices against automated access. never submit forms, accept terms, collect attendee details or bypass restrictions. keep the result here.
when
wednesdays at 11:00, reading the approved page-list file
needs
a bot with its own browser, a permitted page-list file and the fields to collect; no connector

what comes back looks like this (an example, not a real inbox)

fictional workshop listings
workshop | organiser | date shown | location | price | source
repair basics | nelora studio | 18 november | north room | £25 | repair basics page
wood finishing | east hall workshop | not listed | east hall | not listed | wood finishing page
read: 12 november 2026
failed: weekend sessions blocked access. no rows from it.
repair basics mentions materials but lists no separate materials price.

decide what belongs in each cell

keep 'from £25' intact so the next person sees the real offer. pages can mix headline prices, extras and old offers. tell the bot which price to collect and keep wording that changes its meaning.

start with pages you can inspect. compare the first table against them before expanding the list. leave missing values blank and labelled, ready for someone to follow up.

it reads like you would, one page at a time

this reads pages one by one. a bot can have its own browser. screen lets you watch, and take control lets you step in.1 use that to inspect a difficult page. some sites will still block access.

for what the pages mean, use market research. for changes since a previous visit, use competitor monitoring.

choose the pages you may read this way

keep the job to fields you're allowed to collect. read site terms, robots rules and the personal data rules that apply before approving the list. collect only what the job needs.

for company contact research, start with the narrower lead research workflow. decide on outreach separately.

when a page needs sign-in or won't finish loading, have the bot name it beside the table. then you know which sessions still need a look.

the guard rails

  • approve the page list first. read site terms and robots rules before collection.
  • keep personal details out. collect them only when you have a lawful reason.
  • keep the evidence beside the row. include source links and reading dates.
  • show gaps honestly. missing fields and blocked pages aren't permission to bypass access.

try it in 2 minutes

  1. choose two public pages you may read this way
  2. name four fields and what counts as missing
  3. ask for a table with source links and reading dates
  4. compare a row with each original page

keep the source beside the price; you'll need it when a number looks wrong.

before you use the table

  • every row has a source and reading date
  • price qualifiers and currencies survived
  • missing values stay visibly missing
  • failed pages appear separately

mistakes people make

turning 'from £25' into '£25'

keep the qualifier. it changes what the price means.

filling a missing date from another session

leave 'not listed'. put separate sessions on separate rows.

treating failed pages as empty listings

list failures separately so the table's limits stay visible.

what it could save you

roughly 15 minutes per weekly run under these assumptions

6 pages x 4 minutes collecting by hand = 24 minutes
24 minutes - 9 minutes checking the returned table
= 15 minutes per run

a rough estimate. it assumes:

  • six permitted pages each take about four minutes by hand
  • you spend nine minutes checking the whole returned table
  • this is a rough estimate, not a measured result; setup and blocked pages take extra time

questions

can i scrape websites with ai without writing code?

yes. describe the fields and table in chat. begin with a short page list and compare the result with the originals.

what if the website blocks the bot?

this routine stops and names the page. look for another permitted source. don't ask it to evade the block.

can i use the table for lead generation?

company facts, yes. people's personal details, only with a lawful reason. read the site's terms first.
