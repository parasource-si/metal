hear about the competitor changes worth your monday

find the price change before your next sales call. give a bot exact pricing pages and changelogs to compare with dated notes each week.

by the Metal team · checked 12 november 2026 · how we made this

get old wording, new wording and the source in a short report. unchanged pages stay quiet. failed loads get their own note, so you can tell a real change from a page the bot couldn't read.

the routine

save the first baseline and every later comparison has a starting point. give the bot exact pricing and changelog links. compare the first note with those pages, then keep it in your project folder.

paste this into a chat with your bot

every monday at 4pm, read the competitor page list in our project folder using your own browser. compare with the dated baseline there. on the first run, save visible wording, source link, date, currency, billing interval and region where shown. tell me the baseline is ready to review.

on later runs, report only changed prices, included limits, availability or new changelog entries. show old and new wording, source and reading date. keep interpretation separate. ignore navigation, footer and displayed-date changes. save dated records of successful reads.

if a page is blocked or unreadable, say 'read incomplete' and name it. never count missing content as removal or replace the last good baseline. never sign up, buy a plan or contact a competitor.
when
mondays at 16:00, after you review the first baseline
needs
a bot with its own browser, a page list file and a project folder for dated notes; no connector

what comes back looks like this (an example, not a real inbox)

fictional competitor: orinth desk

current: 'team plan includes 5 workspaces', read 12 november 2026.
source: orinth desk pricing page.
the displayed allowance changed. existing customers may have older terms.

the other pages read successfully had no reportable changes.

save the qualifications with the price

save the terms that make the price mean something. monthly and annual billing can show different amounts. region and currency can change the display too. save those details alongside the wording.

keep the original baseline and later dated notes in the project folder.2 compare the first note with the source yourself, then let unchanged pages stay quiet.

decide what earns an interruption

a moved footer isn't a business event. name the changes you care about: prices, included limits, availability or release notes. require old and new wording before drawing conclusions.

use market research for a broader question. use web scraping for repeated fields. a newsletter can draw on reviewed notes later, once you've checked the change.

keep failed reads in the report

know which pages the bot actually read. private discounts, sales calls and changes between weekly visits sit outside the report. a page that wouldn't load belongs in a separate failure note.

missing monday's run? open automations and look at run history. local routines need the computer awake and dusk open. dusk cloud runs them on time, though a blocked competitor page can still fail to load.

the guard rails

  • approve the first baseline. keep dated notes so you can retrace the comparison.
  • match the terms. compare the same currency, region and billing interval.
  • name failed reads. preserve the last usable wording when a page won't load.
  • read without engaging. exclude sign-ups, purchases and contact with the companies.

try it in 2 minutes

  1. put two competitor links in a project file
  2. ask the bot to save a dated baseline
  3. match currency and billing interval against the sources
  4. schedule comparisons only after that record looks right

'read incomplete' tells you where to look. keep that line in the report.

is this a real change?

  • old and new wording are visible
  • currency, region and billing interval match
  • the source loaded successfully
  • interpretation stays separate from the wording

mistakes people make

calling annual pricing a monthly price cut

compare the same billing interval, currency and region.

replacing the baseline after a failed load

keep the last good baseline. mark this read incomplete.

asking for a report even when nothing changed

name the changes that matter, then let unchanged pages stay quiet.

what it could save you

roughly 20 minutes a week under these assumptions

5 pages x 5 minutes checking by hand = 25 minutes
25 minutes - 5 minutes reviewing the change note
= 20 minutes a week

a rough estimate. it assumes:

  • you review five pages weekly and each takes about five minutes
  • the bot's complete change note takes five minutes to review
  • this is a rough estimate, not a measured result; failed reads and initial setup take extra time

questions

can i have an agent only tell me if something changed?

yes. name the changes you want to hear about. the routine also reports failed reads so a blocked page never looks unchanged.

will it catch every competitor price change?

it covers the named public pages at the scheduled time. short-lived changes, private quotes and unreadable pages can escape it.

where does the bot run when my laptop is closed?

use dusk cloud or your own server to keep the weekly read going. on your laptop, it needs dusk open and the computer awake.
