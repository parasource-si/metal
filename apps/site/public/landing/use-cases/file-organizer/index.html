a file organizer bot that lists its moves first

find the receipt without opening half the project folder. give a local bot the folder and ask for a tidy-up plan: where each file would go, what it would be called and why.

by the Metal team · checked 12 november 2026 · how we made this

you approve the moves after opening a separate backup. unclear files stay put, and similar names never turn into permission to delete.

the routine

get a move list you can read before anything moves. make a separate copy yourself and open a few files from it. then give a local bot the project folder, on ask for approval.

paste this into a chat with your bot

every friday at 5pm, inspect only the project folder i gave you. propose a tidy-up here. ask me before you change anything.

- list the current path, proposed path and reason for each move
- group receipts under receipts, reference material under references and unfinished work under working
- suggest clearer names only when the contents justify them
- keep file extensions unchanged

leave ambiguous files, shortcuts, hidden files and app-managed folders alone. flag name collisions. never delete, deduplicate or move anything outside this folder.

wait for me to confirm my tested backup and approve specific moves. compare the paths with the plan again before moving. stop if a file changed or a destination exists. afterwards list only completed operations.
when
fridays at 17:00 for inspection; specific approved moves follow separately
needs
a local bot, one project folder and a separately tested backup; no connected app

what comes back looks like this (an example, not a real inbox)

cedar project: proposed moves
receipt-talvo.pdf -> receipts/receipt-talvo.pdf | contents show a receipt
cedar-style-notes.txt -> references/cedar-style-notes.txt | reference notes
unfinished-copy.txt -> working/unfinished-copy.txt | marked unfinished

left alone: final-final.pdf; purpose unclear
collision: references/cedar-logo.png already exists

no files moved. confirm the backup and choose which moves to apply.

give it one folder with rules you understand

give every destination a job. name a project folder and explain what belongs under receipts, references and working. an old draft might still be a useful reference. "make it neat" leaves those choices to the bot.

point the bot at the project folder itself, not its own workspace.1 the computer-use overview explains the setup; a folder plan needs no screen control.

keep a way back to the originals

keep a separate copy you have actually opened. the move list tells you what changed; the backup gives you the original files. use a separate folder or your normal backup method, rather than relying on automatic undo.

begin on ask for approval. auto-accept edits permits file changes; use that only once you trust the scope.2 the computer safety guide explains the settings.

get the awkward files back as questions

let the bot sort the clear cases and bring you the rest. files called invoice can belong to different customers. have it flag uncertainty rather than force a category.

shortcuts can point outside the folder, and renaming can break links in another document or app. leave app-managed material outside the job and compare completed changes with the plan.

for collected web material, web scraping explains keeping the source information with the files.

the guard rails

  • keep a working backup. open a few files in a separate copy before approving moves or renames.
  • make the schedule inspection only. on ask for approval, let the bot propose named operations for you to choose.
  • keep originals safe at the destination. stop if a path changed or a file already exists. never overwrite, delete or deduplicate.

try it in 2 minutes

  1. make a separate copy of one folder and open a few files in it
  2. give a local bot that project folder
  3. ask for a move plan with no changes
  4. compare one proposed move with the actual file

ask for the current path, new path and reason. you should be able to follow the move without guessing.

mistakes people make

starting with the whole home folder

choose one project you understand and define its destination folders.

deleting files because the names look duplicated

keep them. deciding whether they are duplicates is a separate job.

approving a plan after the files changed

compare the paths again and stop at any mismatch.

before allowing a move

  • the backup opens correctly
  • the current and destination paths match the plan
  • the destination does not already hold a file
  • unclear and app-managed files remain outside the move list

questions

can it organise one folder without touching everything?

give it that project folder and name the boundary. exclude other folders, ask for an inspection-only plan and compare the proposed paths with the files before approving.

can it rename files from their contents?

ask for proposed names first. keep extensions and leave unclear files unchanged. the bot may not be able to read every file type.

is there an undo button for a bad tidy-up?

keep the backup as your way back. do not rely on an undo button. the completed operation list tells you which originals to recover.
