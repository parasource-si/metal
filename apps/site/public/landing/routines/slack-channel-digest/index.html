Metal/routines

an end-of-day digest of the slack channels you choose

stop rereading three channels just to find what changed. get an end-of-day digest of decisions, commitments and open questions from the channels you name.

by the Metal team · checked 12 november 2026 · how we made this

it follows the replies and keeps a message link beside each item. the result comes to your dusk chat. slack can stay read only while you decide which conversation needs your attention.

the message

paste this into a chat with your bot

every weekday at 5:30pm, read today's messages in #heathervale-launch and #heathervale-support. include other channels only when they are named in your job. read relevant replies too, including replies to older parent messages.

return one short digest here:
- confirmed decisions
- explicit commitments, with the person and any stated deadline
- questions still open in the messages you read

include the channel and a message link for every item. call suggestions suggestions. never invent owners or deadlines. skip greetings, repeat announcements and social chatter.

include every named channel and relevant thread. report failed or incomplete reads with the missing coverage. stay quiet only when all reads succeed and nothing substantive remains.

read only the named channels. no direct messages. never post, reply, react, mark messages read or change slack.
when
weekdays at 17:30, in your chosen time zone; covers that day in the named channels
needs
slack read access to the chosen workspace and channels, with history, thread reads and message links

what comes back

an example, not a real run

today in the heathervale channels

- decision: #heathervale-launch, petra confirmed the public demo moves to thursday. source: confirming message at 10:20.
- commitment: #heathervale-support, arthur will test the corrected import file tomorrow morning. source: thread reply at 15:40.
- open question: #heathervale-launch, should the old signup page stay live? source: question at 16:10.

all named channels and relevant threads read successfully.

make it yours

  • start small. choose two named channels. add another only when you know what it contributes.
  • match the working day. change the reporting time or widen the window for a team across time zones.
  • follow a topic. try customer escalations, keeping source links so you can judge the selection.
  • keep it short. cap it at five items and group repeat mentions of the same decision.
  • keep the destination simple. return the digest to dusk chat, where you can read it before sharing.

when it goes wrong

  • a proposal sounds final. require an explicit confirming message. anything weaker stays a proposal.
  • the answer hides in replies. open the thread before calling a question unresolved. report inaccessible replies.
  • yesterday's item appears again. include only the new decision or changed commitment. keep earlier context brief.
  • a failed read looks like silence. report the inaccessible channel. only successful reads can support a quiet result.

keep the discussion one click away

open the decision without hunting for it again. the slack connection supports history, threads and message links. ask for the link beside each item. read sensitive disagreements in full.

a product manager may choose release and feedback channels. an operations lead may need handoffs. remove channels that only add noise.

need a morning view? try a daily briefing. local runs need an awake computer and dusk open.

the best catch-up is short enough to read before you open slack again.

try it in 2 minutes

  1. choose two project channels you already read
  2. connect slack with read-only access
  3. ask for today's confirmed decisions and source links
  4. open one confirming reply before scheduling the digest

what it could save you

roughly 35 minutes a week under these assumptions, not a measured result

10 minutes reading channels each day
- 3 minutes checking the digest and source links
= 7 minutes per day
x 5 workdays
= 35 minutes a week

a rough estimate. it assumes:

  • your current catch-up takes 10 minutes on each workday
  • reading the digest and its important source links takes 3 minutes
  • setup and early corrections are extra time

mistakes people make

asking for a summary of the whole workspace

name the channels. broad catch-ups turn into another inbox.

staying quiet when a channel cannot be read

name the channel it could not read. save silence for days it read successfully.

calling the first suggestion a decision

find the confirming reply and link it.

questions

what are scheduled ai tasks useful for in slack?

a focused catch-up is a good trial. gather decisions, promises and questions you would otherwise hunt for. inspect source links and judge the selection after a few runs.

will the digest be posted into slack?

the digest comes to dusk chat. slack stays read only. posting is a separate job, with its own allowed action and sending setting.3

does it read every channel and my direct messages?

the instruction limits it to named channels. also restrict app access and actions. naming channels guides the job; it does not lock the slack connection to those channels.
